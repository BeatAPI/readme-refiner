# GitHub rendering checks

- Use GitHub Flavored Markdown and ordinary relative repository paths.
- Keep essential explanations and commands in Markdown, not inside images.
- Use fenced code blocks with accurate language tags.
- Keep tables narrow enough to remain understandable on mobile.
- Give every meaningful image descriptive alt text.
- Avoid remote fonts, scripts, embedded HTML applications, and external SVG
  dependencies.
- Preserve a static SVG or image fallback for optional motion.
- Avoid relying only on color to encode meaning.
- Check heading order and generated anchors after renaming sections.
- Prefer repository-owned assets over fragile third-party image services.
- Review both light and dark themes; SVG backgrounds should be explicit when
  transparency would reduce contrast.
- Keep source assets editable and names stable so future README edits do not
  require a complete visual regeneration.
